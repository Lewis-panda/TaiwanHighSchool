# 新版 PDF 章節作者規格

這是 `content/` 產線的唯一作者入口。每章的必要公開交付只有一份能讓學生獨立讀懂、練習與訂正的講義。

## 1. 一章的固定交付

```text
content/<課程>/<章碼>/
├── 學生講義.md
├── assets/
│   └── <章碼>-<圖名>.svg
└── 編輯判定.md              # 本機內部檔，永不進輸出版
```

- 每章恰有一份 `學生講義.md`；它是唯一必要、唯一可登記的新標準 artifact。
- `title` 以章碼開頭；`output_slug` 固定由 `title` 加上 `-學生講義` 衍生。
- 學習目的、概念原理、迷思診斷、完整推理、真實用途與應用邊界都直接寫進學生稿，不依賴另一冊補完。
- 本機若仍保留舊 `教師備課指南.md`，一律受 Git 忽略；scaffold 不建立、lint 不要求、registry 不輸出，`review-*`／`published-*` set 也拒絕 teacher artifact。標準 `build-handout` 不建置它。
- `編輯判定.md` 可記本機教材頁碼、舊稿位置與尚待核對事項；公開稿不得出現 `高中教材/`、本機絕對路徑或內部檔路徑。
- `編輯判定.md` 受 Git 忽略。fresh clone 後，可用 `npm run init-private:chapter -- --course <課程> --chapter-code <章碼>` 為已有合法學生稿補建空白範本；命令不覆寫既有檔，也不取代本機備份。

學生稿只允許下列九個、不重複的單行 frontmatter key：

```yaml
---
title: "<章碼> <章名>"
title-prefix: "學生講義"
subtitle: "<學生會理解什麼、為什麼值得學、能用在哪>"
subject: "<數學、物理或化學>"
course: "<已登記的精確課程名稱>"
audience: "學生版｜核心＋理解"
scope: "<現行主線與延伸界線>"
updated: "YYYY-MM-DD"
output_slug: "<章碼>-<章名>-學生講義"
---
```

尖括號內容都是待替換 placeholder，不代表特定章節已開始製作。`updated` 必須是有效的 `YYYY-MM-DD`。現行 schema 登記 `必修數學`（第一／第二冊）、`數學A`、`數學B`（第三／第四冊）、`必修物理`、`選修物理I`、`必修化學` 與 `選修化學I` 至 `選修化學V`；新增其他課程前須擴充並測試 schema，不能靠相似字串猜測。

## 2. 內容決策順序

每個概念先判斷課綱關係，再獨立判斷大考證據，最後才決定篇幅與呈現層。低頻不等於課綱外；舊教材寫得多也不等於現行主線。

課綱關係：

- `C0`：現行課綱直接明列。
- `C1`：現行教材為支撐 C0 的常態展開或必要工具。
- `C2`：同層次的原理補充、迷思澄清或可選讀延伸。
- `C3`：高中跨冊／選修提前。
- `C4`：大學、舊制、前沿或開放問題。

呈現原則：

- 學生主線以 C0/C1 為骨架，先建立問題與直觀，再給定義、推理、例題與檢核。
- C2 可留給想深入理解原理的學生，但需標明「理解用／可略讀」，且篇幅低於核心內容。
- C3/C4 只有在能解決當前迷思或清楚銜接後續時才放進選讀框，並標明適用範圍；其餘只留在本機編輯判定。
- 大考敘述只可使用已完成逐題覆核的固定年份窗口與官方題目證據；不得把觀察比例改寫成「必考」「常考」或未來預測。
- 舊教材只作術語、範圍、例題層次與迷思校準；不能因舊講義篇幅大就升格為主線。

## 3. 原理、用途與限制

每個核心概念只保留真正相關的層次：

1. 要處理的問題與既有方法的缺口。
2. 量、定義或表示法的設計原理。
3. 公式或方法的推導與成立條件。
4. 可據此預測、比較或設計的事物。
5. 實際使用情境，以及高中模型的適用範圍。

用途必須與概念有可說明的機制連結，例如量測不確定度如何影響製程公差、三角函數如何把週期訊號變成可計算模型。真實系統若需要更高階方法，正文須交代高中模型提供的近似層次。

### 語言密度

- 每句必須提供定義、因果、操作、證據、例題步驟或實務限制；刪除暖場、口號與閱讀指令。
- 標題直接寫概念或問題，不使用 `Why → Why → Why`、`起點檢查`、`先備檢核`、`30 秒檢核`、`停止線`。
- 正向寫出規則。只有真正常見且會改變答案的錯誤，才使用「不是／不能／不要」等警告。
- 不為了製造對比而虛構讀者會犯的錯，也不重複同一限制。

## 4. 學生稿最低結構

1. 開頭直接說明本章問題、能力與用途；必要先備知識在首次使用時簡短補足，不另設檢查關卡。
2. 每節由情境或圖像進入，再給定義、原理或公式；公式交代適用條件、符號、單位或幾何意義。
3. 每個課綱子節至少有兩個逐步示範：一題建立基本操作，一題處理變式、逆向、圖表、資料或模型選擇。
4. 每個課綱子節安排 4–6 題可獨立作答的練習；題目須涵蓋基本、變式、概念／圖表與一題應用或整合。
5. 全章安排 12–20 題分層題與 3–5 題跨節整合題；詳解保留模型選擇、關鍵步驟、單位與結果檢查。
6. 解答說明判斷依據、真正常見的錯誤與合理性檢查。物理解答沿用正文圖示規則，受力、運動或軌道題須以圖建立列式依據。
7. 結尾有一頁可回看的核心整理，篇幅約占全章一成；C2–C4 保持較低視覺權重。

完成度以「學生能否不靠教師口頭補充完成首次學習」判定。課本、114 講義與習作需逐頁核對概念層次、例題類型、圖像與實驗；只核對目次或公式清單不算完成。

## 5. Markdown 與圖檔

- 只用標準 Markdown、LaTeX 與產線已支援的 fenced div；禁止 `[[...]]`、`![[...]]` 與 Obsidian 專用 callout。
- 公開連結只允許 `https:`、`mailto:` 或同頁 `#fragment`；不得連到 repository 內的相對檔案、舊筆記樹或帶帳密／token 的 URL。
- fenced div 可使用 class、id 與既有 `data-kind`；圖片尺寸只用百分比 `width`。禁止 inline `style`、事件屬性、`srcdoc` 與未列入規格的自訂 attribute。
- 章節圖只用 `![替代文字](assets/檔名.svg)`；跨章共用圖才可用 `content/assets/檔名.svg`。
- SVG 必須是靜態、自足檔案，不得含 script、`foreignObject`、外部資源或本機路徑。
- 物理內容先用圖建立受力體、坐標系、方向、幾何關係或等時間狀態，再把同一組符號帶入公式。完成稿每章至少使用三張不同的章內 SVG；數量只是底線，每個主要力學模型仍須有能參與推理的圖。
- 化學內容用圖建立粒子數、鍵結、電荷、反應方向、裝置、能量或濃度變化，再以同一組符號解釋方程式與資料。完成稿每章至少使用三張不同的章內 SVG；粒子比例、原子守恆、電荷守恆、曲線與標示必須互相一致。
- 化學實驗需交代藥品危害、個人防護、廢液處理，以及觀察與推論的區分；圖中裝置連接、試劑位置與氣體流向必須可實際操作。
- 數學函數圖必須從方程數值繪製；對稱、交點、極值、漸近線與標記點要另行計算核對。示意圖不得改變曲線的拓撲關係或暗示不存在的交點。
- 圖說要交代讀圖任務；正文必須實際引用圖中的箭頭、區域、點或斜率，避免只放裝飾圖。
- 新繪圖腳本必須把 `CH` 指向 `content/<課程>/<章碼>`，並明確呼叫：

```python
F.save_to(fig, CH, name, output_subdir="assets", write_pdf=False)
```

- 每張章內 SVG 必須在 `publishing/figures.json` 登記恰一個 generator owner、entrypoint、
  command、inputs 與 SHA-256；不得只提交無來源的手寫 SVG。
- generator 不得在章內留下 PDF、cache 或其他未登記副產物。
- 修改圖像產線或 SVG 後執行 `npm run verify:figures`；它會在兩份空白 temp closure
  重生並比較目前本機 runtime 的兩輪 bytes 與 committed assets。

公開倉庫只保留能重生 `content/` 章內 SVG 的 generator。每支腳本都必須列出可靜態解析的 `FIGURE_OUTPUTS`，輸出位置與登記的章內資產完全一致。

## 6. 登記、建置與驗收

1. Fresh clone 中要繼續編輯的既有章，先依 [`tools/SCAFFOLDING.md`](../tools/SCAFFOLDING.md) 執行 `npm run init-private:chapter -- ...`；它只補建受 ignore 的本機範本。
2. 新章先執行 scaffold dry-run；確認後才以 `--write-approved` 建立空白的學生單冊骨架。這一步不寫教材內容、不修改白名單，也不發布 PDF。
3. 完稿並清除所有 `TODO(SCAFFOLD):` 後執行 `npm run lint:chapter -- --course <課程> --chapter-code <章碼>`，取得恰一個 student document 的 registry 候選。
4. 在 `publishing/sets.json` 每章登記恰一份學生稿與精確 SVG 白名單；teacher document 會被 schema 拒絕。
5. 依序執行 `preflight`、`release`、`verify`、`review:render`。正式 PDF 只取自不可變建置快照；共享 `output/` 不是發布來源。
6. 逐頁檢查彩色與灰階聯絡表，人工確認公式、圖、跨頁、留白、答案、原理解釋與用途說明後才送審。物理圖必須實際參與概念判斷或解題；函數圖的對稱、交點與標記點必須與數值或代數核對一致。

`review` 表示待人工確認，不得因機械 QA 通過就稱為正式發布版。`published` 仍須把人工審過的每份學生 PDF SHA-256 精確綁定到 approval map。
